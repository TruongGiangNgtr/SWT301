# CI and TRX reporting

The workflow `.github/workflows/tests.yml` restores and builds the existing three-project solution in Release on `windows-2025`, then executes four separately filtered suites: the original NUnit 21 and Playwright 9, the approved AI 3, and Razor Pages HTTP integration 4. No deployment is configured. Actions are pinned by commit SHA; permissions are read-only. Browser installation uses the script generated by Playwright 1.55.0.

## Local execution

Run from the repository root with PowerShell 7 and a .NET 10 SDK:

```powershell
dotnet restore SWT.slnx
dotnet build SWT.slnx -c Release --no-restore
pwsh tests/web-e2e/DateTimeChecker.PlaywrightTests/bin/Release/net10.0/playwright.ps1 install chromium
pwsh ci/run-tests.ps1 -Suite unit
pwsh ci/run-tests.ps1 -Suite ai-assisted
pwsh ci/run-tests.ps1 -Suite http-integration
pwsh ci/run-tests.ps1 -Suite web-e2e
pwsh ci/summarize-tests.ps1
```

All commands must succeed; a later passing command does not erase an earlier failure. `-Configuration Debug` is supported when the same configuration was built. `-ResultsDirectory` permits an explicit output directory.

## Guards and evidence

`ci/test-suites.json` is an expected-name manifest, not a results file. Each run first records a unique GUID and `NotExecuted` state, verifies named cases in discovery output, and writes TRX plus discovery/execution logs beneath `TestResults/ci/<suite>/<guid>/`. The NUnit adapter lists all 24 project cases even with a class filter; scoped discovery counts are the matching manifest names. Actual filtered execution and TRX names must still match exactly.

The summary validates the latest run's identity, paths, execution exit status, discovery evidence, TRX counters and unique exact test names. Missing/stale TRX, zero tests, failure, skipped tests, renamed/duplicate cases or a nonzero test command fail the guard. Actual passed/failed/skipped/not-executed counts are displayed. Expected counts never become fabricated passed counts. New legitimate cases require an intentional manifest review.

Summary and artifact upload use `always()`, retaining available evidence after failure. Build/browser failures leave dependent suites unexecuted and fail the summary. No configuration can guarantee upload if a runner is terminated or GitHub is unavailable. Artifacts contain only `TestResults/ci/`, never the application's data-protection key directories. Retention is 14 days. Ten explicit guard self-check scenarios were verified locally; their synthetic negative TRX fixtures are infrastructure tests, not product test results.

## Verification boundary

Local execution passed all 37 scoped cases and YAML passed actionlint. **GitHub runner execution: NOT EXECUTED.** Nothing has been committed or pushed. A real Actions run is required before claiming CI success or artifact availability on GitHub.

Visual regression is run separately on the approved Windows 10 environment. Windows 2025 and Linux have no approved visual baseline; the workflow does not run that gate. This is an explicit suite boundary, not a skipped or disabled failing test. Performance is also a separate approved characterization, not a CI acceptance gate.
